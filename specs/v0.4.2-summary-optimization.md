# DS-001 v0.4.2: Structured Summary Optimization

> **Root Cause:** LLM prompt says "generate a 2-3 sentence Chinese summary" — too short, too vague, no structure. Result: summaries avg ~78 chars, sometimes inaccurate.

## Problem

1. **Too short**: summaries average 78 Chinese chars (observed in vault). Vector search needs more signal.
2. **Inaccurate**: LLM sometimes confuses articles in batch processing (e.g., Hermes Windows article summary describes AgentThreatBench)
3. **No structure**: plain text summary without structured fields

## Fix

### 1. Upgrade LLM summary prompt (`pipeline/llm_filter.py`)

Change from:
```
If relevant, generate a 2-3 sentence Chinese summary.
```

To a structured, longer summary with explicit fields:
```
If relevant, generate a Chinese summary with these sections:

## 摘要
- **主题:** [1 sentence — what is the article about]
- **方法/发现:** [2-3 sentences — key method, result, or insight]
- **意义:** [1 sentence — why it matters]

Total: at least 150 Chinese characters, at most 400.
Return in JSON: {"relevant": bool, "ai_summary": "structured text", "content_type": "..."}
```

### 2. Raise minimum summary length (`collect.py`)

Find `MIN_SUMMARY_CHARS` and raise from current value (likely 50) to **150**.

### 3. Quality gate: reject summaries without expected sections

Add regex check: summary must contain at least one of `**主题:**`, `**方法:**`, `**发现:**` or `**意义:**` markers. If not, log warning and skip the article (don't write broken summaries).

## Files

| File | Change |
|------|--------|
| `pipeline/llm_filter.py` | Upgrade summary prompt with sections |
| `collect.py` | Raise MIN_SUMMARY_CHARS to 150; add section check |

## Acceptance

After fix, run DS-001 against HN + arXiv:
- Average summary length ≥ 150 Chinese chars
- All summaries contain section markers
- No cross-article contamination (spot check 5 random articles)
