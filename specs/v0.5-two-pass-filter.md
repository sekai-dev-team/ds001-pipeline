# DS-001 v0.5: Two-Pass LLM Filter (Relevance → Fulltext Summary)

## Problem

v0.4.3 generates structured summaries from **RSS abstracts** (300 chars), not the actual article fulltext. Fulltext extraction happens AFTER summary generation — the LLM never sees the real content. Result: summaries reflect RSS quality, not article quality.

## Design: Two-Pass Architecture

```
Pass 1 (cheap, all articles): RSS摘要 → relevance check → max_tokens=256
  ├─ irrelevant → discard
  └─ relevant → fetch fulltext (existing fulltext.py logic)
                  ↓
Pass 2 (quality, relevant only): fulltext前4000字 → structured summary → max_tokens=1024
```

## Implementation

### 1. Split `_call_deepseek_single()` into two functions

**`_call_deepseek_relevance(article) -> dict | None`**
- System prompt: only asks for `{relevant: bool, content_type: string}`
- No summary generation — just classification
- `max_tokens`: 256
- `timeout`: 30s

**`_call_deepseek_summarize(article) -> dict | None`**
- System prompt: same structured summary format (主题/方法发现/意义, ≤500 chars)
- Input: article title + first 4000 chars of fulltext (not RSS summary!)
- `max_tokens`: 1024
- `timeout`: 60s
- Only called for articles where fulltext extraction succeeded

### 3. Fulltext extraction integration

Currently `collect.py` does fulltext extraction AFTER LLM filter (Step 3.5). With two-pass:
- Move fulltext extraction between Pass 1 and Pass 2
- Pass 2 uses `article.fulltext` (first 4000 chars) as input
- Articles without fulltext (trafilatura fail, arXiv 429) still get RSS-based summary as fallback

### 4. Fallback for no-fulltext articles

If `article.fulltext` is None/empty after extraction:
- Skip Pass 2 — no fulltext available
- But still mark as relevant and write to vault with RSS summary as ai_summary
- This handles tweets, paywalled articles, arXiv rate limits gracefully
