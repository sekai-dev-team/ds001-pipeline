# DS-001 v0.4.3: Per-Article LLM Filter

> **Root Cause:** Batched LLM calls (up to 50 articles per request) cause cross-article contamination — the LLM confuses article summaries, misattributes content, and a single API failure drops the entire batch.

## Problem

1. **Cross-article contamination**: When 50 articles are sent in one request, the LLM sometimes mixes up facts between articles (observed in v0.4.2: Hermes Windows article summary described AgentThreatBench).
2. **No error isolation**: A single API timeout or parse error marks ALL 50 articles in the batch as not relevant.
3. **Sequential batches**: Batches are processed one at a time — no parallelism.

## Fix

### 1. Per-article LLM calls (`pipeline/llm_filter.py`)

Replace the batch `_call_deepseek(articles: list[Article])` function with a single-article version `_call_deepseek_single(article: Article)`:

- Send **one article per API call**
- Return a **single JSON object** (not an array):
  ```json
  {"relevant": true, "ai_summary": "...", "content_type": "article"}
  ```
- `max_tokens=1024` (reduced from 4096 — one article needs less budget)

### 2. ThreadPoolExecutor with max_workers=5

Process articles concurrently using `concurrent.futures.ThreadPoolExecutor`:

```python
with ThreadPoolExecutor(max_workers=5) as executor:
    future_to_article = {
        executor.submit(_call_deepseek_single, article): article
        for article in articles
    }
    for future in as_completed(future_to_article):
        article = future_to_article[future]
        ...
```

- 5 concurrent workers balances throughput against API rate limits
- Uses `as_completed()` to process results as they arrive (no waiting for slow articles)

### 3. Error isolation per article

Each article's API call is independent:

- Timeout/failure for article A → log warning, mark A as not relevant
- Article B's result is unaffected
- Exception in `future.result()` → caught per-article, logged, continues

### 4. Simplify `filter_articles()`

Remove:
- Summary-length sorting (no longer relevant without batch grouping)
- `MAX_ARTICLES_PER_BATCH` constant
- Batch loop logic

Keep:
- Empty-input guard
- Thread pool processing
- Relevance/content-type filtering logic

### 5. Update SYSTEM_PROMPT

Change response format from JSON array to single JSON object:

```diff
-Return a JSON array of {relevant: bool, ai_summary: string, content_type: string}.
-Always return valid JSON, one object per input article in the same order.
+Return a JSON object with keys: relevant (bool), ai_summary (string), content_type (string).
+Always return valid JSON.
```

## Acceptance

- Each article gets its own API call (no batching)
- `ThreadPoolExecutor(max_workers=5)` visible in `filter_articles()`
- One failed article does not affect other articles' results
- `filter_articles()` is simpler (no batch loop, no summary-length sort)
- `max_tokens=1024` in the DeepSeek API payload
- Existing pipeline tests continue to pass
